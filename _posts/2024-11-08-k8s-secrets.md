Sooner or later a teammate runs `kubectl get secret app-secret -o yaml`, pipes the value through
`base64 --decode`, and reads your database password in plain text, then asks why a "Secret" was so easy to
open. This post is about that gap: how Secrets work, how to inject them, and the one setting that actually
makes them secure at rest.

A **Secret** is structurally a ConfigMap for sensitive values, passwords, tokens, TLS keys. The API is nearly
identical. The difference is intent, and a single dangerous default: **Secret values are base64-encoded, not
encrypted.**

### Creating a Secret

Imperatively, from literals or a file:

```bash
kubectl create secret generic app-secret \
  --from-literal=DB_HOST=mysql \
  --from-literal=DB_PASSWORD=password

kubectl create secret generic app-secret \
  --from-file=app-secret.properties
```

Declaratively, the values under `data` must already be base64 text:

```yaml
# secret-data.yaml
apiVersion: v1
kind: Secret
metadata:
  name: app-secret
data:
  DB_HOST: bXlzcWw=          # echo -n 'mysql' | base64
  DB_USER: cm9vdA==
  DB_PASSWORD: cGFzc3dvcmQ=
```

If you would rather write plain text and let Kubernetes encode it, use `stringData` instead of `data`.

### Injecting a Secret into a Pod

Three ways, from coarse to precise. Load every key as environment variables:

```yaml
spec:
  containers:
    - name: app
      image: app
      envFrom:
        - secretRef:
            name: app-secret
```

Pull a single key into one variable:

```yaml
env:
  - name: DB_PASSWORD
    valueFrom:
      secretKeyRef:
        name: app-secret
        key: DB_PASSWORD
```

Or mount the Secret as a volume, where each key becomes a file (useful for TLS certs):

```yaml
volumes:
  - name: app-secret-volume
    secret:
      secretName: app-secret
```

### The catch: base64 is encoding, not encryption

```bash
echo -n 'mysql' | base64             # bXlzcWw=
echo -n 'bXlzcWw=' | base64 --decode # mysql
```

Anyone who can read the Secret object, or read the etcd datastore behind the API server, can decode it. You
can prove the etcd exposure with `etcdctl`:

```bash
ETCDCTL_API=3 etcdctl \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  get /registry/secrets/default/app-secret | hexdump -C
```

Without encryption at rest, the password is right there in the dump.

### Encrypting Secrets at rest (the real fix)

First define an `EncryptionConfiguration`. The provider order matters: `aescbc` encrypts, and `identity`
(plain text) sits last as the read fallback for already-unencrypted data.

```yaml
# /etc/kubernetes/enc/enc.yaml
apiVersion: apiserver.config.k8s.io/v1
kind: EncryptionConfiguration
resources:
  - resources:
      - secrets
    providers:
      - aescbc:
          keys:
            - name: key1
              secret: <base64-encoded 32-byte key>   # head -c 32 /dev/urandom | base64
      - identity: {}
```

Then point the API server at it and mount the directory (it is a static Pod, so edit its manifest):

```yaml
# /etc/kubernetes/manifests/kube-apiserver.yaml
spec:
  containers:
    - command:
        - kube-apiserver
        - --encryption-provider-config=/etc/kubernetes/enc/enc.yaml
      volumeMounts:
        - name: enc
          mountPath: /etc/kubernetes/enc
          readOnly: true
  volumes:
    - name: enc
      hostPath:
        path: /etc/kubernetes/enc
        type: DirectoryOrCreate
```

Encryption only applies to Secrets **written after** it is enabled. Re-encrypt everything that already exists
by reading and replacing it in place:

```bash
kubectl get secrets --all-namespaces -o json | kubectl replace -f -
```

### Best practices

- **Never commit Secret manifests** to source control; the base64 is not protection.
- **Enable encryption at rest** so etcd stores ciphertext, not just encoded text.
- Prefer `secretKeyRef` over `envFrom` so a Pod only sees the keys it needs.

Confirm a value round-trips as expected:

> kubectl get secret app-secret -o jsonpath='{.data.DB_PASSWORD}' | base64 --decode
